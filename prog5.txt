PART 3 — XSS (Cross Site Scripting)
________________________________________
What is XSS?
XSS allows attackers to inject malicious JavaScript into web pages viewed by other users.
Purpose of attack:
•	Session hijacking 
•	Cookie theft 
•	Redirecting users 
•	Running malicious scripts 
Types:
1.	Stored XSS 
2.	Reflected XSS 
________________________________________
A) Stored XSS
________________________________________
Step 8: Navigate to Stored XSS Page
What to do
In DVWA sidebar click:
XSS (Stored)
Explanation
Stored XSS permanently stores malicious scripts in database/server.
Whenever another user visits the page, the script executes automatically.
________________________________________
Step 9: Inject Basic HTML
What to do

Name: Test
Message: <b>Hello Everyone</b>
Click:

Explanation

Step 10: Inject JavaScript Alert
What to do

<script>alert("Hello This is XSS")</script>

________________________________________
Step 11: Verify Persistence
What to do
•	Move to another DVWA page. 
•	Return to XSS Stored page. 
Explanation
The popup appears again because the malicious script is permanently stored.
This is why it is called:
Stored XSS
________________________________________
Step 12: Display Cookies
What to do
Inject:
<script>alert(document.cookie)</script>
Explanation
document.cookie displays browser cookies.
Cookies often contain:
•	Session IDs 
•	Authentication tokens 
Example:
PHPSESSID=abcd1234
Attackers can steal sessions using this.

PART 4 — CSRF (Cross Site Request Forgery)
________________________________________
What is CSRF?
CSRF tricks authenticated users into performing actions unknowingly.
Example:
•	Changing password 
•	Making payments 
•	Updating profile 
The server trusts the user session automatically.
________________________________________
